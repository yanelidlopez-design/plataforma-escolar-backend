2. COMPORTAMIENTOS CRÍTICOS POR AUDITAR (Tareas Inmediatas para Devin)
================================================================================

[REVISIÓN 01] Validación de Atributos en AsistenciasSerializer:
Devin debe abrir 'apps/academico/serializers.py' y verificar el ReadOnlyField de
'grupo_nombre'. El source está configurado como 'grupo.grado.nombre_grado'.
Dado que el modelo 'GruposAcademicos' declara el campo como:
   grado = models.ForeignKey('core.GradosAcademicos', ..., db_column='id_grado')
Django genera la propiedad de relación automáticamente sobre 'grado'. Sin embargo, si
el backend falla al serializar, Devin debe mutar el source a:
   grupo.id_grado.nombre_grado
Lo mismo aplica para 'seccion_nombre', verificando si requiere mutar de 'grupo.seccion...'
a 'grupo.id_seccion.nombre_seccion'.

[REVISIÓN 02] Coherencia del Campo de Búsqueda en ProfesoresViewSet:
En 'apps/personal/views.py', ProfesoresViewSet define:
   search_fields = ['cedula', 'nombres', 'apellidos', 'especialidad']
Sin embargo, el modelo 'Profesores' en 'apps/personal/models.py' no posee campos
llamados 'nombres' ni 'apellidos'. Utiliza:
   ['primer_nombre', 'segundo_nombre', 'primer_apellido', 'segundo_apellido']
Devin debe corregir inmediatamente 'search_fields' en ProfesoresViewSet y
RepresentantesLegalesViewSet para evitar excepciones 'FieldError' al usar la barra de
búsqueda de Swagger.

[REVISIÓN 03] Seguridad y Encriptación en Creación de Usuarios:
El UsuariosSerializer tiene 'clave_hash' configurado como write_only. Devin debe asegurar
que al realizar un POST a /api/core/usuarios/, la clave no se guarde en texto plano.
Debe implementar el método override de create/update en el serializer o asegurar que
el backend intercepte el string para aplicarle un algoritmo de hashing compatible
con el sistema de login.
